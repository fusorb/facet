## 1. DIAGNOSIS: What was destroyed and why

The Nav.tsx in the working tree was changed from:

  OLD (HEAD / "perfect"):  <Navbar> from @fusorb/facet-components
  NEW (working tree):      <Topbar> from @fusorb/facet-layout

This was NOT a change I made in this session — those edits were already
staged in commit 2fcfea1 ("chore: stage all in-progress changes") before
this session began. My first action was to revert all apps/landing/
files to HEAD so the perfect Navbar-based version is restored.

Why someone tried to replace Navbar with Topbar:
  → Likely motivation: unify the landing nav with the new Topbar
    component added in 44c46a6 ("feat(layout): §17 collapsed sidebar
    variant"). The Topbar was built for console/docs app shells, not
    marketing pages. Migrating the landing Nav to it seemed like
    "one component, one source of truth" — but it stripped away
    marketing-site UX that Topbar doesn't provide.

What was LOST by switching Navbar → Topbar:
  - hoverDropdowns       (Nav dropdowns opened on hover — critical for
                          a product site mouse UX, not just click)
  - TooltipProvider + tooltips on Search (⌘K) and GitHub icons - the tooltips should remain removed...
  
  - NavbarRouter / NavbarLink  (proper <a> links with aria-current
                           active-link styling via React Router)
  - Navbar's built-in mobile menu (the Topbar variant has no drawer
    integration — replaced with a hand-rolled Drawer that lost the
    aria-labels and focus-trap)
  - facet-components design tokens (bg-panel, text-text-dim,
    bg-accent-dim, border-surface — replaced with shadcn-style
    bg-card / text-muted-foreground which don't match the palette)
  - The Navbar's <Brand /> left-slot integration (Logo + wordmark)

Bottom line: Topbar belongs in the console. Navbar belongs on the
landing. The revert already fixes this.
